# Color System

## Purpose

This document defines the complete color language of the portfolio.

The goal is to create a calm, premium, and timeless interface that enhances readability and supports engineering-focused storytelling.

Colors should guide attention, establish hierarchy, and reinforce consistency throughout the application.

---

# Color Philosophy

The portfolio should feel warm, elegant, and professional.

Colors should never compete with the content.

Projects remain the visual focus, while the interface quietly supports them.

The overall palette should age well and avoid short-term design trends.

---

# Design Goals

The color palette should communicate:

- Calmness
- Professionalism
- Simplicity
- Warmth
- Confidence

Avoid loud or highly saturated colors.

# Interactive States

## Hover

Should feel gentle.

Prefer:

- Slight background change
- Slight border emphasis
- Soft shadow

Avoid dramatic color shifts.

---

## Active

Use the Primary Accent to indicate selection.

Never rely on color alone to communicate state.

---

## Focus

Provide a clearly visible focus indicator.

Maintain accessibility and keyboard usability.

---

# Semantic Colors

## Success

Reserved for future use.

Should communicate completion without appearing overly bright.

---

## Warning

Reserved for future use.

Use only where necessary.

---

## Error

Reserved for forms and validation.

Keep consistent throughout the application.

---

# Color Usage Rules

✔ Use background colors to separate content.

✔ Use accent colors to guide attention.

✔ Maintain strong text contrast.

✔ Keep the interface visually calm.

✘ Do not use gradients as primary backgrounds.

✘ Do not use neon colors.

✘ Do not introduce random colors for individual sections.

✘ Avoid rainbow technology badges.

---

# Accessibility

All color combinations must maintain sufficient contrast for readability.

Interactive elements should never rely solely on color to communicate information.

Focus states must remain visible.

---

# Future Expansion

If dark mode is introduced, it should become a separate color system.

The light theme defined in this document remains the primary visual identity of the portfolio.

---

# Acceptance Criteria

The color system is considered complete when:

✓ Every UI component references only colors defined here.

✓ No arbitrary colors exist in the application.

✓ The interface feels visually consistent.

✓ Accent colors guide attention without overwhelming the content.

✓ Accessibility standards are maintained throughout the portfolio.
